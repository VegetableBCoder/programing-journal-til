# 双亲委派

* 双亲委派就是在类加载器尝试加载一个类时不是自己直接去加载, 而是尝试让父加载器去加载这个类

## 优点

* 类相同的判断是类全名相同和类加载器相同才视为同一个类
* 保证对同一个类的加载结果必定是相同的, 也避免了重复加载
* 可以防止核心代码被替换, 比如JDK中的一些类不会被用户自定义的类替换, 

## 缺点

* 双亲委派不能实现类的隔离, 比如在tomcat中运行多个war包, 它的类加载器就需要考虑多个版本依赖的问题, 除了jdk中的一些基础类外, 到每个war的lib目录中加载依赖
* 还有像JDBC, JNDI这种核心代码在jdk代码中, 又需要不同平台适配的应用, 也打破了加载类的双亲委派机制
  * DriverManger如果按照双亲委派机制加载应该是会失败的, 因为jdk核心代码中并没有各数据库的驱动类
  * DriverManager能加载成功实际上是它的loadInitialDrivers方法的作用
  * 在Drivermanager里面使用了ServiceLoder.load()方法使用线程上下文类加载器进行驱动类加载
