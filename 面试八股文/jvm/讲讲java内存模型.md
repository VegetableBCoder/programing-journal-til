# 讲讲java内存模型

## JMM

* Java内存模型是为了屏蔽不同硬件的物理特性区别而设立的一套交互规范, 它保证了java虚拟机能在多线程环境下正确执行代码
* 内存逻辑上分为工作内存和主内存, 主内存是所有线程共享的, 而工作内存是线程私有的
* 某种程度上说主内存可以理解为内存, 而工作内存可以对应CPU缓存和寄存器
* 所有变量都在主内存中存在, 线程在读取时需要先从主内存加载到工作内存再从工作内存读取, 写入时也需要先写入工作内存再写入主内存

## JMM的特性

* 原子性
  * 基本类型的读写都是原子的; 需要注意的是long, double在32位平台上需要两次32位操作, 不是原子的; 在64位上才是原子的
  * volatile的单次读写也是原子的; 
  * atomicInteger等也是原子的; 通过CAS保证其原子性
  * synchronized的临界区操作是原子的
* 可见性
  * 由于多个线程都可能从主内存复制了同一个变量到自己私有的工作内存
  * 可见性需要考虑的问题是某个线程在自己的私有内存修改了变量的值后其他线程能否立即注意到这个变量值的更新
  * volatile通过读屏障和写屏障来保证线程修改变量后强制刷回主内存, 并使其他线程工作内存里面缓存的变量失效 实现可见性
  * synchronized和lock会在进入临界区后将相关变量全部重新从主内存同步一遍, 退出时将修改的变量全部同步回主内存
* 有序性: happens-before规则; if A happens-before B, 那么A在B之前执行,并且A的操作结果对B可见
  * 首先就是volatile会禁止对指令的重排, 这保证写的发生先于对这个值的读取
  * 还定义了锁的释放一定早于后续加锁, 线程start先于run, 结束先于join等规则
