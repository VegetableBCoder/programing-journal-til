# redis Sentinel原理

* 通过一个多个哨兵节点监控集群, 并完成故障切换

## sentinel与主从节点之间的通信

* 定时向主节点发送INFO, 获取主从节点信息
* 通过PUBLISH命令向主节点发送自己的信息
* 根据主节点获取到的从节点信息, 也和从节点建立订阅连接和命令连接, 定时发送INFO命令, 获取偏移量等信息

## sentinel与sentinel之间的通信

* 新的sentinel节点通过PUBLISH发送自己的信息后, 原来的节点就能通过订阅的频道收到新节点的信息
* 收到新的sentinel节点后, 就建立与新节点的命令连接

## 下线检测

* sentinel向连接的节点选向发送PING命令, 如果没有收到回复则认为其主观下线
* 主观下线之后要向其他sentinel节点确认节点是否下线, 如果确认其下线的节点超过阈值则认为其客观下线

## sentinel之间的leader选举

* 类似于raft, 但是要先和其他sentinel节点进行确认, 确认master客观下线才开始投票
* 选举时发起投票的节点先把自己设置为局部leaeder, 然后要求其他节点也把自己设置为局部leader
* 发起投票请求的节点根据epoch和run-id给自己计票, 如果过半节点把自己设置为局部leader则自己成为全局leader

## redis主节点故障转移过程

* sentinel master先确认主节点客观下线, 然后从候选的从节点列表中选出节点成为新的leader
  * 排除下线的节点, 排除最近没有回复INFO命令的节点
  * 排除所有过早与原来的redis主节点过早断开的节点
  * 按照节点优先级和复制偏移量, 节点id选出新的主节点
* 向主节点发送命令 slave of none 使其成为主节点
* 向其他节点发送slave of 命令, 使其成为新的主节点的从节点
