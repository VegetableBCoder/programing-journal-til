# redis集群原理

* 不论是主从 还是sentinel, 每个节点都需要保持整个库的完整内容, 如果库非常大, 那么需要的内存也就很大, 而集群模式是分布式的方案
* 将计算分为16384个槽, 再将槽分给多个节点负责, 每个节点又可以有一些从节点左读写分离和故障转移

## 故障转移

* 所有节点都会和其他节点相互建立连接, 发送PING命令检测是否掉线
* 当一个节点没有回复自己, 就将其会标记为疑似掉线, 并在集群里面广播这个节点疑似下线的消息
* 如果半数以上的主节点都认为某个节点下线了, 则视为其已经下线并开始选举
  * 参与投票的不是和自己负责同一段slot的节点, 而是存活的其他主节点
  * 从节点要求存活的其他主节点投票给自己
  * 主节点会投票给第一个要求投票的节点, 返回ACK表示支持
  * 从节点根据投票情况, 如果得票过半则变成主节点
  * 如果没有得票过半, 则等一会儿再发起投票
* 新的主节点对自己执行slave of none变成主节点
* 撤销槽指派, 指派给自己
* 广播自己成为主节点, 并接管了原来主节点负责的槽
