# Redis热key

* 热key需要注意的分布不均是给不同节点带来不同的压力
  * 大量请求给到同一个节点, CPU顶满, 如果处理不过来就会拥塞
  * 热key过期可能击穿缓存

## 热key监控

* 客户端可以埋点统计key的使用频率
* promethues监控key的绝对访问QPS和占整个系统的QPS比例
* 同时还得考虑key大小的影响, 比如一个较大的key被频繁访问, 其热度应该要比小key相同频率访问的热度要大


## 热点预测

* 业务预测: 比如秒杀商品必然是热点
* 历史分析: 对某些可能定期成为热点的key进行预测
* 行为分析: 用户标签+行为, 比如经典的明星发结婚微博
  * 可以拦截它们的发布行为, 先分析处理再发布成功

 
## 解决

* 前端缓存: 尽量减少客户端重复加载的行为
* CDN缓存: 静态资源可以通过CDN避免流量来到后端
* 二级缓存: 减少请求redis的次数, 降低redis压力
