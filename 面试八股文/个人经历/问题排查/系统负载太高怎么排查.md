# 系统负载太高怎么查

## IO负载太高(网络IO)

### 带宽占用太多

* 如果是带宽占用很高, 用nethogs监视一下哪个进程占用的带宽多
* 占用的

## CPU占用太多

* 通过cat /proc/loadavg 可以显示最近 1min 5min 15min的cpu负载; 需要注意的是这里的负载并不是1为满值, 而是约等于核数就是满值; 第四个是可运行的进程和系统中的总进程, 第四个是系统最近创建的进程id 
  * 容器内看不到宿主机的总进程数, 所以第四个得在物理机上看


* 通过top, 查看CPU的利用率; 这里是多个核的平均利用率, 如果需要看每个核的详情, 使用top -1
  * us: 用户态占用率, 占用过多说明有大量计算型任务在占用CPU
  * sy: 内核态占用率, 占用太高说明可能可能有大量的网络连接处理, 中断, 磁盘IO, 锁竞争
  * wa: IO等待, 常见于机械硬盘随机读
  * id: 空闲CPU
  * si: 软中断, 网络带宽很高可能会出现
  * st: 自己用的是虚拟机, 宿主机CPU资源超卖, 可能云厂商偷你的CPU资源给别人了, 赶紧投诉去
  

* 使用`top -H -p <PID>` 查询线程的CPU使用情况

## 负载高 利用率不高

* 注意看top命令里面wa的比例(IO等待)
  * 占比很高可能磁盘存在瓶颈
  * 可能大量请求都在请求相同的IO, 导致了堆积
* 物理机上看 cat /proc/loadavg, 如果运行进程少, 说明确实是IO瓶颈, 或者锁竞争激烈
* ps -axjf看到的D状态进程多, wa为0 说明是IO严重阻塞


## 负载不高, 利用率高

* top -o %CPU找到占用率高的进程
* 然后观察它的线程
* `top -H -p <PID>`
* 然后把线程id变成id进制 `print "%0x%x\n" <PID>`
* 通过`jstack <PID> | grep <16进制线程ID>` 定位线程状态和方法调用栈, 确定代码在执行什么东西
  * jstack命令也会展示线程的CPU时间和创建了多久
