# HashMap相关

## 讲讲HashMap

* hashMap使用了一个数组加链表的方式来存储数据
* 默认初始容量是16, 扩容因子是0.75, 容量保证为2的n次方
* 当数据插入map时, 计算hash, 对容量取余(实际是通过与capacity - 1 进行按位与实现的), 得到所在的slot
* 当slot内没有元素时, 直接新建一个节点, 放在slot上, 如果已经有节点了, 则放在链表的尾部
* 当链表的长度达到8时, 对链表进行树化,转化为红黑树
* 如果容量超过capacity*扩容因子, 需要对整个map进行扩容, 扩容到两倍大小
  * 由于节点的位置是hash的低位, 扩展map大小后, 新使用到的位为1的将会移动到原来index+原来size(新size一半)的位置上, 如果为0则留在原地
  * 如果红黑树的节点<8则将其退化为链表

## Java 8相对于Java7对HashMap做了些什么优化?

### 头插法改为尾插法

* 头插法在并发扩容时会出现循环链表问题; 假设某个slot上有链表 A-B-C
* 当一个线程正在扩容, 加入其读取了第一个元素 A, next=B, 将A.next指向null
* 此时另一个线程完成了扩容, 将原来的 A-B-C变成了 C-B-A
* 正在扩容的线程继续执行, newTable[i]=e, 此时slot里面的元素变成A,
* 迭代当前元素到 B, 将B的next指向A, 然后又将B插入slot中, 继续往A遍历, 死循环卡死在里面
 
* 总的来说hashmap可以线程不安全, 但是不应该出现这种死循环的问题; 所以java8改成了尾插法

* 由于链表是单向链表, 所以尾插法复杂度是O(N), 头插法是O(1)

#### 为啥尾插法不会?

* 因为尾插法不会使链表出现扩容时倒过来的情况, 不会出现原来在后面的元素引用前面的元素


### 树化

* 当链表节点数>=8时变成红黑树, 方便使用hashcode快速定位
* 也算是弥补一下头插改尾插的性能损失
* 当size<64时, 如果需要树化, 会先进行扩容

### hash函数扰动

* java7让高12位, 高20位进行混合, 再与原值进行混合, java8是高16和第16混合
