# 查询为啥不走索引

## sql写法问题

* 对列进行运算
* 参数类型和列类型不一致
* 不满足最左匹配原则
* like 不是前缀匹配
* ...

## 优化器分析

* 无法建立扫描区间: 比如不满足联合索引的最左匹配原则
* 成本分析的前置条件有问题: 索引的统计数据有问题, 所以成本估算不对
* 成本分析: sql认为走全表扫描成本更低, 比如特别小的表; 或者扫描索引返回行数占全表的行数太大, 也就是索引区分度不足
* 索引选择: 有的地方认为可能会走索引合并, 但是实际上优化器却没有走合并
* 总之, 得看执行计划
* 连表的时候驱动表和被驱动表的选择和写sql的时候预期不一致
  * 预期A表作为驱动表, 走索引查询数据, 再从B表扇出数据
  * 实际上B表作为驱动表, 再从A表扇出数据, 可能不会使用预期的A表二级索引

## 成本分析

* IO和CPU成本
  * IO是要加载的数据页成本: 也就是估算的加载页数*每页加载的成本, 以及回表的成本(假设二级索引每查处一条数据都要回表加载一次页面)
  * CPU成本: 回表判断的成本; 某些情况还有索引下推的成本, 索引下推可以降低回表的IO成本
