# HTTP和HTTPS

* HTTP是明文传输的, HTTPS是加密传输的协议
* 验证成功后需要使用非对称加密方式进行密钥协商
  * 客户端发送自己的TLS版本, 支持的对称加密方式给服务端, 另外还会携带一个随机数
  * 服务端校验TLS版本和加密方式并选择一个加密方式返回给客户端作为后续使用的加密方式, 另外还有一个随机数
  * 服务端将自己的证书发送给服客户端
  * 客户端从证书服务器和自己信任的证书列表中校验证书, 并确认证书是否在有效期内
  * 客户端使用客户端和服务端的随数生成一个密钥作为对称加密的密钥
  * 客户端使用证书的公钥信息加密对称加密密钥发给服务端, 服务端使用私钥解密密钥, 记录这个密钥作为后续通信的对称加解密密钥

## 为什么说HTTPS是安全的?

* 防窃听: 除了握手过程中的部分通信, 都是加密的, 中间人无法解析通信报文内容
* 防篡改: 任何修改都会导致无法解密传输的内容
* 防伪装: 使用权威机构的服务进行证书核验


## HTTPS的改进: ECH

* 提前跟DNS一起公布一个公钥用来加密
* 客户端发现自己要用https访问一个域名, 就会查域名的DNS信息这些
* 客户端发现有ECH的配置, 就把这个公钥给存起来, 用来ClientHello握手使用
  * 客户端生成的一个临时密钥对, 通过ECH公钥+自己的私钥生成一个对称的密钥, 
  * 用对称的密钥对clientHello内容, 并附上自己的临时公钥发给服务端

### CDN对ECH的支持

* 比如cloudflare, 他们让用户在平台上生成密钥对, 就可以解析加密的sni并进行处理
