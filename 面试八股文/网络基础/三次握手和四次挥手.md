# TCP连接

## 三次握手

```
client -> server: SYN=1, seq=x
server -> client: SYN=1, seq=y, ACK=true, ack=x+1
client -> server: ACK=true, ack=y+1  
```
* TCP规定 SYN=1的报文不能携带数据, 所以只有客户端最后一次ACK的时候可以携带报文


## 四次挥手

```
client -> server: FIN=1, seq=x
server -> client: ACK=true, seq=y, ack=x+1
sever继续传输没有完成的数据发送
server -> client: FIN=1, ACK=true, seq=y1 ack=x+1
client -> server: ACK=true, seq=x+1, ack=y1+1
```

* 发给客户端的最后一条数据+第三次挥手的FIN一起发给客户端
* 如果没有给客户端的数据报文要发送, 第二次和第三次挥手可以一起合并发给客户端


## TCP的优化

* 拥塞控制: 发送方慢启动, 逐渐调大窗口, 如果发生丢包, 则需要缩小窗口
  * 不同算法窗口变化规则不一样

## 建⽴和处理连接的是同⼀个socket吗，socket中两个队列分别是啥

* 不是同一个, Linux内核中有两个队列, 一个是半连接队列, 一个是完成连接的队列
  * 半连接队列是指服务端收到了SYN, 但是三次握手还没完成的队列
  * 完成三次握手之后从半连接队列取出放在完成连接的队列
* 单边连接问题
  * 服务端给了客户端ACK回应, 但是自己全连接队列容量不足, 可能会丢弃连接, 就会出现客户端认为自己连接成功, 实际上没有连接的问题
